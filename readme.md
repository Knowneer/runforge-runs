Фронтенд-интерфейс дашборда запусков AI-агентов (Runs) для платформы Runforge.

Live Demo: https://runforge-runs-snowy.vercel.app/

Стек и технологии:
1.React 18 + Vite
2.CSS Modules (изолированная стилизация в фирменной палитре Runforge, полная адаптивность от 360px)
3.Vitest + React Testing Library (автотестирование основных сценариев)
4.Локальный Mock-сервис на базе Promise с задержкой для демонстрации состояний загрузки и сетевых ошибок.

Функциональность:

1.Список запусков: вывод названия, репозитория, ветки, статуса (с цветным индикатором и двойной подписью), времени создания и длительности.

2.Фильтрация и поиск: совместная работа кнопок статусов (All, Queued, Running, Succeeded, Failed) со счётчиками элементов и живого поиска по названию или репозиторию.

3.Детали запуска (Drawer): боковая панель с подробными метаданными, результатами выполнения и терминальными логами (с поддержкой закрытия по клику вне области и клавише Escape).

4.Все состояния интерфейса: фирменный лоадер (MyLoader), обработка ошибок с кнопкой «Повторить попытку» и пустой результат сброса фильтров (EmptyState).

Структура проекта

src/
├── UI/                  # Переиспользуемый UI-кит (MyButton, MyInput, MyLoader)
├── components/          # Смысловые блоки (Header, Filters, RunsList, RunDetailsDrawer, States)
├── data/                # Локальный mock-сервис и набор запусков (mockRuns.js)
├── App.jsx              # Главный компонент, управление стейтом и фильтрацией
├── App.test.jsx         # Автотесты (Vitest)
└── index.css            # Глобальные стили, переменные и шрифты


Установка и запуск:

1.Установите зависимости:
npm install

2.Запустите проект в режиме разработки:
npm run dev


3.Сборка проекта для продакшена:
npm run build

Запуск автотестов:

Для проверки ключевых сценариев (фильтрация, поиск, открытие деталей) выполните:
npm test


Проверка основных сценариев вручную:

1.Загрузка: При открытии отображается фирменный лоадер, после чего загружается список из 6 запусков.

2.Фильтрация: Клик по кнопке статуса оставляет в таблице только соответствующие элементы, обновляя счётчики на кнопках.

3.Поиск: Ввод текста в инпут мгновенно фильтрует список. При отсутствии результатов показывается блок сброса.

4.Детали: Клик по строке запуска открывает выдвижную панель с логами.

5.Ошибка: Кнопка «Тест ошибки» в шапке переключает интерфейс в состояние сбоя с кнопкой повтора запроса.
